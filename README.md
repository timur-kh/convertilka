# Конвертилка — конвертер файлов в браузере

Статичный сайт (HTML + CSS + JS, без сборки и npm). Все конвертации выполняются на устройстве пользователя, а файлы никуда не отправляются.

## Что умеет

| Группа | Читает | Сохраняет |
|---|---|---|
| Изображения | PNG, JPG, WebP, AVIF, GIF, BMP, ICO, TIFF, SVG, HEIC | PNG, JPG, WebP, AVIF*, BMP, ICO, TIFF, PDF (+ несколько картинок в один PDF) |
| Документы | DOCX, PDF, Markdown, HTML, TXT | PDF (с кириллицей), HTML, Markdown, TXT, PNG/JPG (страницы PDF) |
| Таблицы | XLSX, XLS, ODS, CSV (UTF-8 и Windows-1251), JSON | XLSX, ODS, CSV (`,` `;` или табуляция), JSON, HTML |
| 3D | STEP, IGES, BREP (CAD), STL, OBJ, PLY, GLB, glTF, FBX, 3MF, DAE | STL, OBJ, PLY, GLB, glTF, USDZ |

\* только если браузер умеет кодировать AVIF; иначе формат скрыт в списке.

Для всех форматов есть предпросмотр: изображения, страницы PDF, документы и таблицы (в изолированной песочнице) и 3D с вращением мышью.

## Структура

```
site/                  ← ЭТО и только это публикуется на хостинг
  index.html           главная (конвертер)
  support.html         пожертвования и ввод кода «без рекламы»
  privacy.html         политика конфиденциальности (допишите контакты!)
  licenses.html        лицензии библиотек
  sw.js                service worker (кэш для офлайн-работы)
  _headers             заголовки безопасности (Cloudflare Pages / Netlify)
  assets/js/config.js  ← ВСЕ НАСТРОЙКИ: ссылки на донаты, реклама, ключ кодов
  assets/js/…          код сайта
  vendor/              сторонние библиотеки (скачаны tools/vendor.mjs)
tools/                 служебные скрипты (на хостинг не попадают)
tests/                 самотест
```

## Запуск локально

Нужен только Node.js (он уже установлен).

```bash
node tools/serve.mjs          # → http://localhost:8080
```

Если открыть `index.html` двойным щелчком (`file://`), сайт работать не будет: браузеры не загружают JS-модули с диска.

## Публикация

Сайт полностью статичный, поэтому подойдёт любой хостинг. Публикуется **папка `site/`**.

- **Cloudflare Pages** (рекомендую: бесплатно, быстрый CDN, понимает `_headers`): создайте проект и укажите `site` как каталог сборки, команду сборки оставьте пустой.
- **Netlify**: перетащите папку `site` в панель, `_headers` подхватится сам.
- **GitHub Pages**: работает, но `_headers` не поддерживается. Основная защита (CSP в `<meta>`) всё равно действует.
- **Свой сервер (nginx/Apache)**: перенесите заголовки из `site/_headers` в конфиг сервера.

Обязательно используйте HTTPS: без него не работает service worker (офлайн-режим).

После каждого обновления сайта увеличьте `VERSION` в `site/sw.js`, чтобы у посетителей обновился кэш.

## Пожертвования и коды «без рекламы»

Сервер не нужен. Вы подписываете коды своим **закрытым** ключом, а сайт проверяет подпись **открытым** ключом (ECDSA P-256 через WebCrypto). Подделать код без закрытого ключа невозможно.

1. Один раз создайте ключи:
   ```bash
   node tools/supporter-keygen.mjs
   ```
   Выведенный `supporterPublicKey` вставьте в `site/assets/js/config.js`.
   Файл `tools/keys/private.pem` **никому не показывайте, не публикуйте и сохраните резервную копию**: если он потеряется, придётся выпускать новые ключи, и старые коды перестанут работать. Он уже добавлен в `.gitignore`.
2. Впишите ссылки на Boosty / Ko-fi / ЮMoney и т.п. в `config.js → donate`.
3. Когда приходит пожертвование, выпустите код и отправьте его человеку:
   ```bash
   node tools/supporter-sign.mjs 30      # код на 30 дней (+3 дня запаса)
   node tools/supporter-sign.mjs 365 5   # пять кодов на год
   ```
4. Человек вводит код на странице «Поддержать». После этого реклама и рекламные скрипты у него не загружаются.

Ограничение: код можно передать другому человеку, это плата за то, что сервер не нужен. Позже выдачу можно автоматизировать: webhook платёжного сервиса → бесплатная serverless-функция (например, Cloudflare Worker) подписывает код и отправляет его на почту.

## Реклама

По умолчанию реклама **выключена**, и сайт не загружает ни одного стороннего скрипта.

Чтобы включить рекламу:
1. В `config.js → ads` поставьте `enabled: true`, выберите `provider` (`yandex` — РСЯ, или `adsense`) и впишите ID блоков. Места под рекламу: `top`, `side`, `bottom`.
2. **Расширьте CSP** в `<meta http-equiv="Content-Security-Policy">` в `site/index.html`. Иначе браузер заблокирует рекламу. Примерные добавки (сверьтесь с актуальной документацией сети):
   - **РСЯ**: в `script-src`, `connect-src` и `frame-src` добавьте `https://yandex.ru https://*.yandex.ru https://yastatic.net https://*.yandex.net`, а в `img-src` добавьте `https:`
   - **AdSense**: в `script-src` добавьте `https://pagead2.googlesyndication.com https://*.googlesyndication.com https://*.google.com https://*.gstatic.com https://*.doubleclick.net https://*.adtrafficquality.google`; в `frame-src` и `connect-src` — `https://*.doubleclick.net https://*.google.com https://*.googlesyndication.com https://*.adtrafficquality.google`; в `img-src` — `https:`
3. Проверьте страницу: откройте консоль (F12) и убедитесь, что нет ошибок `Content-Security-Policy`.

⚠️ Важно для честности перед пользователями: рекламный скрипт выполняется на той же странице, что и конвертер. Технически он может прочитать содержимое страницы. Файлы не загружаются на сервер **нами**, но доверие к сайту теперь зависит и от рекламной сети. Поэтому:
- в тексте сайта утверждается только то, что верно («файлы не загружаются на наш сервер»);
- пользователи с кодом поддержки получают страницу вообще без сторонних скриптов (это можно упомянуть как ещё один плюс доната).

## Безопасность

- Строгий **CSP**: скрипты только со своего домена, `eval` запрещён, сторонние запросы запрещены, `<object>` и встраивание сайта в чужие фреймы запрещены.
- HTML из DOCX/Markdown/HTML/таблиц проходит через **DOMPurify**: вырезаются скрипты, обработчики событий, формы, iframe, `javascript:`-ссылки и внешние картинки (трекинг-пиксели). Затем он показывается в `iframe sandbox=""` без права на скрипты.
- 3D-модели **не могут обращаться к сети**: ссылки на внешние текстуры и буферы подменяются пустыми данными.
- SVG растеризуется через `<img>`, где скрипты не выполняются.
- pdf.js работает с `isEvalSupported: false` и без XFA.
- Все библиотеки лежат локально (`site/vendor/`, версии и SHA-256 в `MANIFEST.txt`), CDN не используется.
- Аналитики и cookie у самого сайта нет.

## Обновление библиотек

Поменяйте версии в `tools/vendor.mjs` и запустите:
```bash
node tools/vendor.mjs
```
Затем прогоните самотест.

## Тесты

```bash
node tools/serve.mjs                                              # в отдельном окне
node tests/run-headless.mjs                                       # 52 проверки конвертаций и предпросмотра
node tests/run-headless.mjs http://localhost:8080/ 10 tests/ui-scenario.js   # сценарий в интерфейсе
```
Самотест можно открыть и в обычном браузере: http://localhost:8080/tests/selftest.html

Если стоит антивирус Kaspersky, в консоли будут ошибки CSP с доменом `kaspersky-labs.com`. Это антивирус встраивается в страницы на localhost, к сайту это отношения не имеет.

## Идеи на будущее

- **SEO-страницы** под популярные запросы («HEIC в JPG», «DOCX в PDF», «STL в OBJ») с тем же конвертером. Это главный источник трафика для таких сайтов.
- Английская версия (больше аудитория и дороже реклама).
- OBJ вместе с MTL и текстурами (загрузка нескольких файлов как одной модели).
- Тяжёлые конвертации в Web Worker, чтобы интерфейс не подвисал на больших файлах.
- Распознавание текста в сканах PDF (Tesseract.js) и PDF → DOCX.
