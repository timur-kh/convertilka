# Конвертилка — конвертер файлов в браузере

Статичный сайт (HTML + CSS + JS, без сборки и npm). Все конвертации выполняются на устройстве пользователя, а файлы никуда не отправляются.

## Что умеет

| Группа | Читает | Сохраняет |
|---|---|---|
| Изображения | PNG, JPG, WebP, AVIF, GIF, BMP, ICO, TIFF, SVG, HEIC | PNG, JPG, WebP, AVIF*, BMP, ICO, TIFF, PDF (+ несколько картинок в один PDF) |
| Документы | DOCX, PDF, Markdown, HTML, TXT | PDF (с кириллицей), DOCX (из PDF), HTML, Markdown, TXT, PNG/JPG (страницы PDF) |
| Книги | FB2 (в т.ч. .fb2.zip, Windows-1251), EPUB | EPUB 3, FB2, PDF, DOCX, HTML, TXT |
| Таблицы | XLSX, XLS, ODS, CSV (UTF-8 и Windows-1251), JSON | XLSX, ODS, CSV (`,` `;` или табуляция), JSON, HTML |
| 3D | STEP, IGES, BREP (CAD), STL, OBJ, PLY, GLB, glTF, FBX, 3MF, DAE | STL, OBJ, PLY, GLB, glTF, USDZ |
| Видео | MP4, MOV, MKV, WebM, AVI, WMV, FLV, M4V, 3GP, MPEG, GIF | MP4, WebM, MOV, MKV, AVI, GIF, MP3, M4A, WAV, OGG, FLAC |
| Аудио | MP3, WAV, OGG, Opus, M4A, AAC, FLAC, WMA, AIFF, AMR | MP3, M4A, WAV, OGG, Opus, FLAC |

\* только если браузер умеет кодировать AVIF; иначе формат скрыт в списке.

Видео и звук обрабатывает FFmpeg в WebAssembly (ffmpeg.wasm). Ядро весит ~31 МБ и загружается при первой конвертации медиа, потом берётся из кэша. Смена контейнера (MKV/MOV → MP4) идёт без перекодирования и занимает секунды; полное перекодирование видео в браузере заметно медленнее настольных программ. Долгую конвертацию можно отменить.

**Инструменты:** сжать изображение (JPG → JPG/WebP), сжать PDF (перерисовкой страниц — для сканов), объединить PDF и картинки в один PDF (порядок — перетаскиванием), сжать видео до заданного размера в МБ с вариантами качества.

**Видео и звук:** в предпросмотре видны все звуковые дорожки с графиком громкости (в децибелах, со шкалой времени и пиком); громкость каждой меняется от −30 до +30 дБ (с лимитером), есть «Нормализовать»; лишние дорожки удаляются. Кодеки выбираются для каждого файла.
Два движка: **FFmpeg (WebAssembly)** — любые форматы, H.264/ProRes/VP8/MPEG-4 и все аудиокодеки; **WebCodecs (через Mediabunny)** — H.265, AV1, VP9 и быстрый H.264 силами браузера и видеокарты. Какие кодеки доступны, сайт проверяет на устройстве пользователя: H.265 обычно есть в свежих Chrome/Edge при видеокарте с аппаратным кодированием. «Сжать до размера» считает варианты с учётом эффективности кодека; в «Тонких настройках» — частота кадров, ключевые кадры, видеокарта/процессор, битрейт звука, моно.

Для всех форматов есть предпросмотр: изображения, страницы PDF, документы и таблицы (в изолированной песочнице) и 3D с вращением мышью.

## Структура

```
site/                  ← ЭТО и только это публикуется на хостинг
  index.html           главная (конвертер)
  privacy.html         политика конфиденциальности (допишите контакты!)
  licenses.html        лицензии библиотек
  sw.js                service worker (кэш для офлайн-работы)
  _headers             заголовки безопасности (Cloudflare Pages / Netlify)
  assets/js/config.js  ← ВСЕ НАСТРОЙКИ: ссылки на донаты, реклама, ключ кодов
  assets/js/…          код сайта
  vendor/              сторонние библиотеки (скачаны tools/vendor.mjs)
tools/                 служебные скрипты (на хостинг не попадают)
tests/                 самотест
```

## Запуск локально

Нужен только Node.js (он уже установлен).

```bash
node tools/serve.mjs          # → http://localhost:8080
```

Если открыть `index.html` двойным щелчком (`file://`), сайт работать не будет: браузеры не загружают JS-модули с диска.

## Страницы под поисковые запросы (SEO)

Страницы вида `/heic-to-jpg/`, `/step-to-stl/` — это та же главная с уже выбранным форматом и **собственным** текстом и вопросами. Тексты лежат в `tools/seo/pages.mjs`, страницы собирает скрипт:

```bash
node tools/build-pages.mjs
```

Он создаёт `site/<адрес>/index.html`, обновляет блок «Популярные конвертации» на главной, `sitemap.xml` и `robots.txt`. **Запускайте его после любой правки главной страницы или текстов**: страницы пар собираются из главной как из шаблона (меняются только участки между метками `<!--seo:…-->`).

- **Домен.** Пока в `tools/build-pages.mjs` стоит `SITE_URL = 'https://example.ru'`. Когда появится домен — поменяйте и перезапустите.
- **Новая страница.** Добавьте запись в `tools/seo/pages.mjs`. Пишите действительно свой текст про особенности пары: страницы, где меняются только названия форматов, поисковики считают дорвеями и понижают весь сайт. Перед добавлением проверьте спрос в Яндекс Вордстате / Google Keyword Planner.
- **После запуска сайта:** добавьте его в Яндекс Вебмастер и Google Search Console и отправьте `sitemap.xml`.

### Статьи о форматах

Страницы `/formats/png/`, `/formats/pdf/` и т.д. — «что это за формат и чем открыть» с конвертером этого формата наверху, таблицей фактов, блоком «Чем открыть» и ссылками на конвертации. Тексты — в `tools/seo/formats.mjs`, справочник всех форматов — `/formats/`. Собираются той же командой `node tools/build-pages.mjs`; генератор предупреждает о ссылках на несуществующие страницы.

## Публикация

Сайт полностью статичный, поэтому подойдёт любой хостинг. Публикуется **папка `site/`**.

- **Cloudflare Pages** (рекомендую: бесплатно, быстрый CDN, понимает `_headers`; лимит 25 МБ на файл соблюдён — большие файлы библиотек нарезаны на части): создайте проект и укажите `site` как каталог сборки, команду сборки оставьте пустой.
- **Netlify**: перетащите папку `site` в панель, `_headers` подхватится сам.
- **GitHub Pages**: работает, но `_headers` не поддерживается. Основная защита (CSP в `<meta>`) всё равно действует.
- **Свой сервер (nginx)**: готовый фрагмент конфигурации — `deploy/nginx.conf` (типы файлов wasm/js, заголовки безопасности, сжатие, кэш). Все библиотеки сохраняются с расширением `.js`, поэтому сайт работает и без настройки типов `.mjs`.

Обязательно используйте HTTPS: без него не работает service worker (офлайн-режим).

После каждого обновления сайта увеличьте `VERSION` в `site/sw.js`, чтобы у посетителей обновился кэш.

## Реклама

По умолчанию реклама **выключена**, и сайт не загружает ни одного стороннего скрипта.

Чтобы включить рекламу:
1. В `config.js → ads` поставьте `enabled: true`, выберите `provider` (`yandex` — РСЯ, или `adsense`) и впишите ID блоков. Места под рекламу: `top`, `side`, `bottom`.
2. **Расширьте CSP** в `<meta http-equiv="Content-Security-Policy">` в `site/index.html`. Иначе браузер заблокирует рекламу. Примерные добавки (сверьтесь с актуальной документацией сети):
   - **РСЯ**: в `script-src`, `connect-src` и `frame-src` добавьте `https://yandex.ru https://*.yandex.ru https://yastatic.net https://*.yandex.net`, а в `img-src` добавьте `https:`
   - **AdSense**: в `script-src` добавьте `https://pagead2.googlesyndication.com https://*.googlesyndication.com https://*.google.com https://*.gstatic.com https://*.doubleclick.net https://*.adtrafficquality.google`; в `frame-src` и `connect-src` — `https://*.doubleclick.net https://*.google.com https://*.googlesyndication.com https://*.adtrafficquality.google`; в `img-src` — `https:`
3. Проверьте страницу: откройте консоль (F12) и убедитесь, что нет ошибок `Content-Security-Policy`.

⚠️ Важно для честности перед пользователями: рекламный скрипт выполняется на той же странице, что и конвертер. Технически он может прочитать содержимое страницы. Файлы не загружаются на сервер **нами**, но доверие к сайту теперь зависит и от рекламной сети. Поэтому:
- в тексте сайта утверждается только то, что верно («файлы не загружаются на наш сервер»);

## Безопасность

- Строгий **CSP**: скрипты только со своего домена, `eval` запрещён, сторонние запросы запрещены, `<object>` и встраивание сайта в чужие фреймы запрещены.
- HTML из DOCX/Markdown/HTML/таблиц проходит через **DOMPurify**: вырезаются скрипты, обработчики событий, формы, iframe, `javascript:`-ссылки и внешние картинки (трекинг-пиксели). Затем он показывается в `iframe sandbox=""` без права на скрипты.
- 3D-модели **не могут обращаться к сети**: ссылки на внешние текстуры и буферы подменяются пустыми данными.
- SVG растеризуется через `<img>`, где скрипты не выполняются.
- pdf.js работает с `isEvalSupported: false` и без XFA.
- Все библиотеки лежат локально (`site/vendor/`, версии и SHA-256 в `MANIFEST.txt`), CDN не используется.
- Аналитики и cookie у самого сайта нет.

## Обновление библиотек

Поменяйте версии в `tools/vendor.mjs` и запустите:
```bash
node tools/vendor.mjs
```
Затем прогоните самотест.

## Тесты

```bash
node tools/serve.mjs                                              # в отдельном окне
node tests/run-headless.mjs                                       # 106 проверок: конвертации, предпросмотр, видео и звук (FFmpeg и WebCodecs), правки дорожек, сжатие, книги, PDF → Word, объединение PDF
node tests/run-headless.mjs http://localhost:8080/ 10 tests/ui-scenario.js   # сценарий в интерфейсе
```
Самотест можно открыть и в обычном браузере: http://localhost:8080/tests/selftest.html

Если стоит антивирус Kaspersky, в консоли будут ошибки CSP с доменом `kaspersky-labs.com`. Это антивирус встраивается в страницы на localhost, к сайту это отношения не имеет.

## Статистика и позиции в поиске

**Посещаемость — Яндекс.Метрика.** Создайте счётчик на metrika.yandex.ru (Вебвизор не включайте), впишите его номер
в `ANALYTICS.metrikaId` в `tools/build-pages.mjs` и выполните `node tools/build-pages.mjs`. Генератор сам добавит счётчик
на все страницы, откроет домены Метрики в Content-Security-Policy и покажет абзац о статистике в `privacy.html`.
Пустой номер — всё убирается обратно. В Метрику уходят цели: `convert` (from/to), `download`, `download_zip`,
`share` (platform), `thanks_popup` — только форматы и действия, без имён и содержимого файлов.

Google Analytics (`ANALYTICS.gaId`) — по желанию. Для сайта, работающего в РФ, передача данных Google — трансграничная:
по 152-ФЗ об этом нужно уведомить Роскомнадзор. Трафик из Google и так виден в Метрике.

**Позиции в поиске** — Яндекс.Вебмастер (права подтверждены файлом `site/yandex_*.html`) и Google Search Console
(код подтверждения — в `ANALYTICS.googleVerification`, или подтвердите через DNS). В обоих добавьте
`https://convertilka.com/sitemap.xml`.
